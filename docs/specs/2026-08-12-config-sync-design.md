# 账户库同步（WebDAV / Google Drive）设计

- 状态：**WebDAV v1 已实现**（2026-08-12，随 v1.2.0-beta 发出；Google Drive
  后端仍未实现）。与本稿的两处有意偏差：「仅 Wi-Fi」选项未做（需引
  connectivity 插件，且载荷 <4KB/账户）；冲突入口为设置同步卡片状态行 +
  详情页列表，未做首页卡片角标。§待实测清单 1-4 仍未跑（坚果云/Nextcloud/
  NAS 真机、SDA 反向解密、多账户重登节流）。
- 范围：账户库（maFiles + manifest）跨设备同步。WebDAV 免费先行；
  Google Drive 挂 Pro、排在 paywall 之后（且 play flavor 专属）。
- 参考：SDA `FileEncryptor.cs` / `Manifest.cs`（格式权威，已在
  `docs/plans/2026-08-09-sda-ecosystem-gaps.md` §P0 核对过）、RFC 4918
  （WebDAV）、[ASF wiki · Two-factor authentication](https://github.com/JustArchiNET/ArchiSteamFarm/wiki/Two-factor-authentication)。
- 相关代码：`core/crypto/ma_file_crypto.dart`（密码学，已有）、
  `core/sda_import.dart`（目录导入语义，已有）、
  `services/auto_login.dart`（无头重登，已有）、
  `core/models/steam_guard_account.dart` 的 `toExportJson`（密码剥离开关，已有）、
  `services/account_store.dart`（本地库读写）。

## 目标与非目标

**目标**：一台设备上的账户改动（新增、删除、密码更新）自动出现在其他设备上；
新设备只凭「服务器 + 同步口令」即可取回全部账户，并借 `AutoLogin.ensureSession`
在首次使用各账户时无头重建本设备自己的 Steam 会话。

**非目标**：
- **不同步 Steam 会话**（`Session` 节）。会话是设备绑定的活数据：refresh token
  会轮换（`session_manager.dart` 自己就处理 Steam 发回新 token 的分支），两台
  设备共享一个 token 各自刷新会互踢。密码是静态数据，同步它 + 各设备自行登录，
  冲突模型干净且效果等同。「session 接种」（新设备用远端 refresh token renewal
  出自己的 token）备案为 v2——**预期因无必要而不会实施**；若实施，前置实测项是
  renewal 是否吊销旧 token。
- 不做后台常驻同步（Android 上尤其不引入 WorkManager——CLAUDE.md 硬性约束记录过
  其启动期组件写入风险；前台同步已够用）。
- 不自建同步后端。开发者不持有用户账户数据是隐私政策立场,替用户保管验证器
  密文是纯增负债。
- ~~应用设置同步不在 v1~~ —— **2026-08-12 用户定：做，默认开**（详情页开关
  「同步应用设置」）。同步的是**精选集**：皮肤、明暗模式、长按确认、触觉、
  阻止截屏、上架自动预勾选（manifest 字段）。**刻意排除**：语言与字号（设备
  相关偏好）、device_id 与 entitlement（Pro 设备绑定,同步即权益错乱）、隐私
  同意版本（per-install 重新征求）、PIN/生物识别、一次性 UI 标记、同步配置
  自身。机制：远端 `ava.settings.r<rev>.<dev>.json`（同口令加密,rev 后缀 +
  GC 同账户文件）,sidecar 记 `settings` 条目;合并是 **Lamport rev 的整文档
  LWW,无冲突 UI**——设置项低风险、两步可改回,账户库「绝不 LWW」的原则不
  适用于此。两条关键规则：**新设备首次接触一律采纳远端文档**（绝不用出厂
  默认值覆盖其他设备的选择）;双方都改过时**本机改动胜出**（它是本机所知
  最近的用户动作）。

## 为什么是 WebDAV 先行

- 唯一同时服务两个渠道的方案:cn 用户有坚果云,海外有 Nextcloud / NAS——后者
  正是 ASF 多账户、自托管人群手里已有的东西。Google Drive 天然 play 专属。
- 生态先例:SDA++ Mobile 的卖点就是 WebDAV 同步。
- 零新依赖:所需动词（PROPFIND / GET / PUT / MKCOL / DELETE + `If-Match`）在
  现有 http 栈上手写最小客户端即可,不触碰「依赖升级必须单开批次含出包」约束,
  也无 cn 渠道门禁风险。鉴权 v1 只做 Basic（限 TLS 或用户明示的例外,见 §传输
  安全）;遇到只认 Digest 的服务器再补。

**商业分层**：WebDAV 免费——「数据自由」是承诺不是卖点;Google Drive 的
「一键省心」才是 Pro 卖的东西,与免广告、付费皮肤同属一个价值包。

## 远端格式:就是一个 SDA 加密文件夹

```
<remote-root>/
  manifest.json        # SDA 格式,encrypted=true,每 entry 带 salt/iv
  <steamid>.maFile     # SDA 加密:整文件一段 base64
  ava.sync.json        # AVA 侧车(SDA 不认识、不会读):墓碑、修订号、设备表
  ava.settings.json    # 预留,v1 不写
```

远端不是 AVA 私有格式,而是 SDA / steamguard-cli / AVA（1.1.0 的目录导入）都能
读的标准加密文件夹——「数据不锁死在我这」从口号变成可验证的事实。已知代价与
边界,都明说:

- **KDF 是 SDA 的 PBKDF2-HMAC-SHA1 / 50000 轮**,按今天标准偏弱。且密码字段的
  加入使泄露后果比纯密钥更持久（session 可一键全端吊销,密码得挨个改）。补偿
  全部落在同步口令强度上:**最短 8 字符（2026-08-12 用户定,初稿为 12）,
  设置时带强度条**,低于下限直接拒绝而不是仅警告;强度条刻意由长度主导,
  引导用户往长了设（§UX）。
- **manifest.json 是明文**（SDA 格式如此）,泄露面 = steamid 列表 + 账户数。
  可接受,写进风险提示。
- **ASF 读不了加密 maFile**（wiki 原话 "ASF can't decrypt SDA files"）。ASF
  交接走 AVA 现有的明文导出——默认不含密码,在这里恰好正确。
- 若用户把桌面 SDA 直接指向远端目录并保存,SDA 会重写 manifest 并**丢掉侧车
  以外它不认识的字段**——侧车文件本身不受影响（独立文件名,SDA 不碰）。文档里
  注明「远端目录请只交给 AVA 管理」即可,不做技术对抗。

**同步载荷 = `toExportJson(includePassword: true)` 再剥 `Session` 节,整体过
`MaFileCrypto` 加密。** 密码在 maFile JSON 内部,随文件一起加密,manifest 上
看不见。

## 同步引擎

**每账户一文件 + ETag 乐观锁,无整库 blob。**

- 本地每账户维护单调递增修订号 `rev`（Lamport 计数,不用墙钟排序;墙钟只用于
  展示）。侧车 `ava.sync.json` 存各账户 `rev`、删除墓碑
  `{steamid, rev, deletedAt}`、见过的设备列表。
- 一轮同步 = GET 侧车与 manifest（记 ETag）→ 逐账户比较 rev:
  - 仅远端新 → 拉取解密入库;
  - 仅本地新 → PUT maFile + 更新 manifest/侧车,全部带 `If-Match`;
  - **双方都动过**（同一账户在两台设备各自改过,现实中几乎只有「两边都改了
    密码」）→ 标记冲突,交给 UI 二选一（§UX）,不自动 LWW;
  - 墓碑 rev 高于本地 rev → 本地删除（进回收站语义:移入本地 `trash/` 留 30 天,
    误删可救);本地新增 rev 高于墓碑 → 复活,墓碑清除。
- 任一 PUT 收到 412（ETag 不匹配）→ 重拉、重合并、重试,上限 3 轮后报错,
  **绝不盲目覆盖**。
- 触发时机:应用启动、账户库任何写操作后（去抖 5s）、手动下拉。全部前台执行。
- 口令验证:拉到远端后先试解一个 maFile（`MaFileCrypto` 错口令返回 null),
  解不开就是口令错,**不报文件损坏**——与 1.1.0 导入同一条已验证的判别逻辑。
- 首次绑定已有数据的远端:走一遍与 SDA 目录导入相同的合并语义（本机已有的
  账户按 rev 合并而不是跳过),UI 先出预览再动库。

## 传输安全

- WebDAV 凭据（服务器密码/应用密码）存 `flutter_secure_storage`,绝不进
  账户库、绝不进远端。
- TLS 证书:系统信任链默认;**自签名按指纹逐服务器信任**（首连出示指纹,用户
  确认后钉住),不提供「忽略证书校验」全局开关。
- 明文 HTTP(2026-08-12 用户定):**默认公网必须 HTTPS**;私网主机允许 HTTP,
  过醒目警告即可——payload 本身是 E2E 加密的,但 **Basic 凭据会明文过线**,
  警告必须点名这一条。「私网」按字面主机判定:loopback、RFC 1918 / ULA 字面
  IP、`*.local`(mDNS)。**公网域名即便解析到内网 IP 也不算**——判定只看用户
  输入的字面量,不看 DNS 结果(否则解析结果一变,警告过的配置静默变成明文过
  公网)。
- **公网 HTTP 的风险自担 override**(2026-08-12 用户定):普通路径直接拒绝并
  提示改用 HTTPS / 内网 IP;高级设置里提供逐服务器的「允许该服务器走明文
  HTTP」开关,开启需长按确认(项目惯例),确认文案不含糊:「WebDAV 密码将以
  明文经公网传输,任何中间节点都能读到并登录你的服务器;账户数据本身仍是
  加密的」。该开关按服务器记忆,换服务器地址即失效重问;绝无全局「关闭
  HTTPS 要求」开关。

## UX（入口、流程、可选项）

### 入口

设置 → 新增「同步」分区。未配置时一行「设置同步…」;已配置时显示状态行
（服务器主机名、上次同步时间、成功/冲突/错误三态图标）+ 进入详情页。

**欢迎页第三个 CTA「从同步恢复」**(2026-08-12 用户定):空库首次打开时,
与「登录 Steam」「导入 .maFile」并列,进同一个配置向导——恢复场景下首次
合并预览自然全是下载。向导完成回退后账户已就位,_Root 自动切到主页。

### 首次配置向导（新远端 / 已有远端两条路径同一入口）

1. **选后端**:WebDAV（免费）/ Google Drive（Pro 徽章;cn flavor 整项隐藏,
   play 未解锁 Pro 时点击进 paywall）。
2. **填服务器**:URL / 用户名 / 密码。已知提供商的坑内置成提示文案:坚果云要
   「应用密码」不是登录密码（附后台路径),Nextcloud 给 `remote.php/dav/...`
   示例。**URL 未写协议头时自动补全 `https://`**(2026-08-12 用户定):明文
   HTTP 必须是用户亲手敲出 `http://` 的结果,敲了也仍要过 §传输安全 的警告
   /override 关卡才被接受。**另有「文件夹」输入框**(2026-08-12 用户定):留空
   = 库直接放在 URL 处;填写 = 放入该子文件夹,测试连接时检查并自动创建
   (MKCOL,父目录缺失则逐级向上补建)。**「测试连接」按钮**先行,失败信息区分:DNS/超时、401（密码错）、
   自签名证书（进指纹确认流程)。
3. **探测远端**:目录空 → 「创建新同步库」,设置同步口令（最短 8 字符 +
   强度条 + 「口令丢失 = 数据无法找回,我们无法重置」的不可跳过声明);
   目录有数据 → 「连接到已有同步库」,输口令,错了明说口令错。
4. **首次合并预览**:列出「将下载 N 个账户 / 将上传 M 个 / 冲突 K 个」,
   逐条可展开,确认后才动库。第二台设备的典型路径就是这一步全为下载。
5. 完成页给一句「各账户首次使用时会自动重新登录;存过密码的无需操作,
   没存的会提示输一次」——把 `ensureSession` 的行为预先讲明,避免「同步完
   怎么还要登录」的困惑。

### 同步详情页的可选项(带默认值)

| 选项 | 默认 | 说明 |
|---|---|---|
| 自动同步 | 开 | 关闭后仅手动。启动 + 改动后去抖触发 |
| 同步账户密码 | 开 | 关闭则载荷走 `includePassword: false`;文案说明关闭后新设备每账户要手输一次密码。**该开关改动触发全量重推** |
| 仅 Wi-Fi 同步(移动端) | 关 | 载荷极小(每账户 <4KB),默认不限流量 |
| 立即同步 | — | 手动触发,显示逐文件进度 |
| 查看远端 | — | 只读列出远端账户与修订时间,排查用 |
| 更改同步口令 | — | 全量重加密重推,期间禁止其他设备写(侧车加锁标记) |
| 断开同步 | — | 二选一确认:「保留远端数据」/「同时删除远端」,后者长按确认(项目惯例:不可逆操作长按) |

### 冲突与错误的呈现

- 冲突不弹窗打断:首页对应账户卡片挂角标,同步分区计数。点开出对比页
  (两侧修订时间、来源设备名),**二选一,被弃的一侧自动存入本地 `trash/`**,
  与墓碑回收站同一机制——任何路径都不存在「选错即永失」。
- 同步失败静默重试一轮,再失败才在同步分区亮红,绝不弹阻断式对话框;
  账户操作(生成码、确认)永远不被同步状态阻塞——**同步是账户库的影子,
  不是它的门**。
- 新设备扫码接力(P1 锦上添花,可砍):详情页生成二维码,内含服务器 URL +
  用户名(**不含 WebDAV 密码与同步口令**,两者仍需手输——摄像头旁窥风险
  不值得省这两次输入)。

## Google Drive(v2,Pro,play flavor 专属)

- 复用 play flavor 已有的 Google 登录栈(Credential Manager +
  `kGoogleServerClientId`),Drive 走 REST + `drive.appdata` scope:应用私有
  隐藏目录,无需文件选择器,用户 Drive 界面里也看不见杂物。
- **远端布局与 WebDAV 完全同构**(同一套文件、同一套侧车、同一个口令),同步
  引擎只换传输层——`SyncTransport` 接口:`list / get / put(ifMatch) / delete`,
  WebDAV 用 ETag,Drive 用文件 `headRevisionId` 充当。
- **前置**:`drive.appdata` 是敏感 scope,OAuth 同意屏幕要过 Google 应用审核
  (以周计)——这是它排在 paywall 之后的实际理由之一,审核应在动工前先提交。
- cn flavor 不含任何 Drive 代码路径(channel 门控,与 ads/billing 同一套隔离)。

## 待实测清单(实现前逐条打钩)

1. 坚果云:应用密码 + WebDAV 根路径;免费户有流量/请求频率限额,验证一轮
   20 账户同步的请求数在限额内(引擎已按「侧车先行,无变化则零文件传输」设计)。
2. Nextcloud 与至少一种 NAS(群晖):ETag 在 PUT 后是否稳定、`If-Match` 是否
   真的 412(有服务器实现是弱 ETag 或干脆忽略条件头——若忽略,乐观锁退化,
   需检测并警告)。
3. `MaFileCrypto` 加密产物被桌面 SDA 原版成功解开(反向兼容实证,拿真 SDA 跑)。
4. 新设备全量拉取 + 首次 `ensureSession` 重登的节流表现(连续多账户登录是否
   触发 Steam RateLimitExceeded;若触发,重登本来就是惰性的,只需确认不主动
   预热)。
5. (仅当 v2 session 接种复活)renewal 是否吊销旧 refresh token。

## 验收要求

不能只测「能同步」。纯 Dart 层(合并、墓碑、rev 冲突、口令判别)全部单测,
不碰网络;传输层用内存假服务器测 412 重试与弱 ETag 降级;端到端至少覆盖:
双设备增删改各向传播、双边修改出冲突且两侧数据都可找回、错口令报口令错、
断网中途恢复不产生半写状态、「同步账户密码」开关关闭后远端确无密码字段、
以及**关闭同步后本地一切照旧**(回归)。
