# 更新检查与桌面自更新

2026-08-14 起草。承接 `2026-08-09-sda-ecosystem-gaps.md` 的 P2「桌面自动更新」。

**分两步做**：第一步只告知不安装，第二步才动可执行文件。
（版本号定在 v1.3 / v1.4：v1.2.0-beta 已被 WebDAV 同步占用。）这样切是因为 80% 的价值
（用户压根不知道有新版）来自第一步，而 100% 的风险集中在第二步。

---

## 现状（2026-08-14 实测）

| 事实 | 影响 |
|---|---|
| 桌面端**没有任何包类型标记**（无 `AVA_PACKAGE` 之类） | app 无法判断该下 portable / setup / AppImage，必须先补构建期 define |
| release 只有 **AppImage + portable.exe + setup.exe** 三件 | 无 macOS 产物 |
| 二进制**没有代码签名**（无 Authenticode、无公证） | 操作系统层面的完整性校验不存在，只能自建 |
| `core/entitlement.dart` 已用**内嵌 Ed25519 公钥离线验签** | 更新清单照此模式即可，不是新机制 |
| `PRIVACY.md` §3 逐条列出所有网络连接 | 加检查就要改，且**两处**（仓库正本 + 线上手工 HTML） |

### 发布流程要加的一步

写进 `b`（bump）的清单：改 pubspec → 补 CHANGELOG → 出包 → 传 R2 与 GitHub
→ **更新 worker 的版本端点并部署** → **curl 端点核对版本号与下载链接可达**。
最后两步漏掉不会有任何报错，只会让所有客户端查到旧版本，或查到一个 404 的
下载链接。

**macOS 不在本计划内**（2026-08-14 决定）。顺带记一笔：`README.md` 仍写着
「Windows · macOS · Linux · Android from a single codebase」，而 macOS 既不构建
也不发布——站点的下载区是诚实的（只列 Android/Windows/Linux），README 不是。
这条该单独修。

## 第一步（目标 v1.3）：只告知

不下载任何可执行内容，不引入任何执行外来代码的路径。

| 渠道 | 行为 |
|---|---|
| Android / play | 打开 Play 商店页面 |
| Android / cn | 打开 `https://ava.dotslash.pro/#download`，**不做应用内下载安装** |
| 桌面（三种包） | 提示「有新版本 x.y.z」+ 打开 `https://ava.dotslash.pro/#download` |

**给人看的页面是 `ava.dotslash.pro`，不是 `dl.dotslash.pro`。** 后者是 R2 公开桶
的直链宿主，**按设计不提供目录列表**（Cloudflare 文档：public buckets do not let
you list the bucket contents at the root），根路径是空的。要让它变成一个页面得
往桶里放 `index.html` 并在前面挂 Worker——没必要，站点的下载区已经是那个页面，
而且它的「直发 apk」按钮本来就指向 `dl.dotslash.pro` 上的直链。

分工固定下来：**`dl` 放文件，`ava` 放页面。**

### cn 版为什么不做应用内安装

这批人最需要更新提示（他们没有任何商店会告诉他们），但应用内装 APK 需要
`REQUEST_INSTALL_PACKAGES`，是整个应用里风险最高的一处权限。跳浏览器让用户
自己装，价值几乎相同，风险低一个数量级。

### 硬性纪律

**play 渠道绝不能包含下载 / 安装 APK 的代码。** 与 ads/billing 同级的约束：
只能挂在 cn flavor 上，并且 `mapping.txt` 那道门禁要**一并扩展**去卡它，
不能靠自觉。（见 CLAUDE.md「构建渠道」。）

## 第二步（目标 v1.4）：桌面自我替换

### 完整性锚点：签名清单

产物没有代码签名，所以唯一可信的锚点必须自建：

1. 发布时生成 `latest.json`：版本号、每个产物的**文件名 + SHA-256 + 大小**。
2. 用**独立于 entitlement 的发布密钥**签名（两把钥匙用途分离；entitlement 私钥
   泄露不应等于可以给用户推任意二进制）。
3. app 内嵌该发布公钥，**先验签清单，再比对下载产物的 SHA-256**，两步都过才
   碰这个文件。
4. **绝不静默安装。** 展示将要发生什么，用户确认。

验签的代码形态照抄 `core/entitlement.dart`，那里已经跑通。

### 分发源

**版本源：Cloudflare Worker 上的无记录端点**（2026-08-14 用户定）：
`version.json` 由 worker 提供（`infra/entitlement-worker` 加一条只读路由，或
独立小 worker），**该端点不写任何日志、不存任何请求数据**。

**「没法悄悄过期」的要求不因此消失，只是换了形态**：版本号不再随站点提交走，
而是随 worker 部署走。所以发布清单里必须有「更新 worker 的版本常量并
`wrangler deploy`」这一步，并且**发完当场 curl 一次端点核对版本号**——
`site.ts` 的 `TAG`/`VERSION` 停在 v0.80.1 九个版本没人发现的教训，换个存放处
一样适用。

**用 JSON 不用纯文本。** 需要按平台与渠道分别给版本号、下载链接与校验值，
纯文本要么塞不下要么得自定义分隔格式；JSON 还能加字段而不破坏老客户端。

**产物本身仍然从 `dl.dotslash.pro`（R2）下载**，GitHub 作后备——理由是
2026-08-09 确认过的：GitHub 对国内大量用户不可达，而 R2 出网免费。
**分工：`ava` 说有什么版本，`dl` 提供文件。**

### 按渠道与平台分条

一份清单要同时服务五种客户端，键必须能唯一定位：

```
android-play      → 版本号；动作 = 打开 Play 页面
android-cn        → 版本号；动作 = 打开 ava.dotslash.pro/#download
windows-portable  → 版本号 + 文件名 + SHA-256
windows-setup     → 版本号 + 文件名 + SHA-256
linux-appimage    → 版本号 + 文件名 + SHA-256
```

Android 两条**不带下载信息**，因为第一步和第二步都不在应用内装 APK。

### 各平台替换手法（互不相同，别指望一套代码）

**Windows 便携版**：正在运行的 exe 不能删，但**可以改名**。所以是
「下载到临时目录 → 校验 → 把当前 exe 改名为 `.old` → 新文件写到原名 →
重启 → 下次启动时删掉 `.old`」。失败要能回滚（把 `.old` 改回去）。

**Windows 安装版**：下载 setup.exe，校验，运行它然后退出。它已经支持
`--auto`（`desktop-release.yml:102` 的冒烟测试就在用这个参数）。

**Linux AppImage**：替换文件本身，**必须保留可执行位**。还要处理它位于只读
挂载点、或属主是 root（装在 `/opt`）的情况——**那时应当退回「打开下载页」，
不是报错失败**。

### 前置：构建期打包类型标记

工作流出包时用 `--dart-define=AVA_PACKAGE=win-portable|win-setup|linux-appimage`
写进二进制，app 据此决定下哪个文件。缺了这个，第二步无从谈起。

**坑**：这个 define 必须和 `AVA_CHANNEL` 一样有安全的缺省值，且缺省不能是
「我是便携版」——猜错会让 app 去替换一个不是它自己的文件。缺省应当是「未知」，
行为退化成第一步（只提示、开下载页）。

## 启动时自动检查（2026-08-14 决定）

**每次启动自动拉一次 `version.json`。** 有两条约束不能破：

### 一、绝不能让启动等网络

CHANGELOG 与推广文案都写着「启动过程里没有任何一步在等网络」，离线可用是这个
应用对外承诺过的性质。所以这次拉取必须是**首帧之后触发、完全不阻塞、失败静默**
——超时、无网络、DNS 失败、返回不是合法 JSON，全部当作「本次没有更新信息」，
不弹任何东西。

**验收里要有一条离线启动的测试**，断言启动路径不 await 这次请求。否则这条承诺
会在某次重构里悄悄失效，而没有人会注意到——除非用户在飞机上打开它。

### 二、连接本身要写进隐私政策，哪怕什么都不收集

端点定为**无记录**：不写日志、不存任何请求数据（2026-08-14 用户定）。
「不收集」写进政策没问题，但**这仍然是一次网络连接**，必须列进 `PRIVACY.md`
§3 的连接清单——那一节列的是「应用会连到哪里」，不是「谁在存数据」。
措辞照 §3 现有条目的写法：连到哪、传了什么（版本号与平台，在 URL/UA 里）、
我们不存储任何内容；同时注明请求经 Cloudflare 网络送达（边缘基础设施可见来源
IP，这不由我们控制）——如实陈述，不替基础设施打包票。

**同步改线上那份**（`~/sync/Git/dotslashpro/ava/public/privacy/index.html`，
手工维护、没有生成脚本）。只改一处就是让商店条目指向的政策与应用行为脱节。
这个项目已因隐私说明写得比实际宽返工过一次（v1.0.1），这次**先写政策再发功能**。

**自动检查默认开启**（2026-08-14 用户定），设置里保留关闭开关。

## 验收要求

第一步：版本比较（含 `1.10.0 > 1.9.0` 这类字典序陷阱）、网络失败时静默不打扰、
渠道分支正确（play 不含 cn 的跳转，反之亦然）。

第二步额外：签名错误的清单**必须拒绝**、SHA-256 不符**必须拒绝**、下载中断、
磁盘满、目标只读、替换失败后能回滚、以及「未知包类型」退化成只提示。
这些都要有测试——一个能下载并执行代码的路径，不能靠手点几下就算验过。
